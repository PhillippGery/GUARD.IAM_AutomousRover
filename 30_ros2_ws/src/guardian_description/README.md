# guardian_description

Xacro/URDF robot model for GUARDIAN (no meshes checked in yet — placeholder geometry only).

## Nodes

None. This package only contains URDF/xacro and Gazebo world files.

## Topics

None directly — `robot_state_publisher` (launched from `guardian_bringup`) consumes this package's URDF to publish `/robot_description` and TF.

## Files

| File | Purpose |
|------|---------|
| `urdf/guardian.urdf.xacro` | Single shared robot model for sim and real — `use_sim:=true/false` toggles the simulation-only `<gazebo>` blocks (MecanumDrive plugin, gpu_lidar sensors) |
| `urdf/dimensions.xacro` | AUTO-GENERATED by `20_hardware/cad/step_to_description.py` — measured wheel/lidar dimensions, don't hand-edit |
| `meshes/*.stl` | AUTO-GENERATED by the same script, from the CAD assembly |
| `worlds/guardian_world.sdf` | Gazebo simulation world |

## How to Use

Not run directly — included by `guardian_bringup`'s `guardian.launch.py` via `xacro`:

```bash
ros2 launch guardian_bringup guardian.launch.py                 # sim (default)
ros2 launch guardian_bringup guardian.launch.py use_sim:=false  # real hardware
```

When a new CAD revision replaces the current one:
```bash
python3 20_hardware/cad/step_to_description.py path/to/NewCAD.STEP
colcon build --symlink-install --packages-select guardian_description
```

## Known Issues / Dependencies

- Wheel base and wheel radius in the xacro must match `guardian_bringup/config/robot_params.yaml` after the physical build.
- No mesh files yet — visual/collision geometry is primitive shapes only.
- Must include T265 camera frame, LIDAR frame, and arm base frames for a correct TF tree once CAD is finalized.
- Depends on `xacro` for macro expansion at launch time.
